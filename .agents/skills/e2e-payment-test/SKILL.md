# 綠界成功付款 E2E

使用 Playwright MCP，以使用者可見操作完成一次最短成功付款流程。不得直接呼叫專案 API、修改資料庫、注入 JavaScript、偽造 callback 或付款結果。

## 固定範圍

只執行以下流程：

1. 開啟隔離瀏覽器並進入網站。
2. 使用測試帳號登入。
3. 選擇一項有庫存商品加入購物車，數量維持 1。
4. 前往結帳，以有效測試資料建立一筆訂單。
5. 進入綠界 staging，完成信用卡付款與 3D 驗證。
6. 返回本站，確認顯示「付款完成」。

不要執行結帳欄位驗證、付款失敗、取消付款或其他額外案例。不要為了測試建立第二筆訂單。

## 安全限制

- 僅允許 `ECPAY_ENV=staging`；不是 `staging` 就立即停止。
- 綠界頁面必須是 staging 網域。遇到正式網域、真實扣款提示、CAPTCHA、瀏覽器安全警告或無法判斷環境時立即停止。
- 只能使用本文指定的綠界測試卡，不得使用真實信用卡或自行猜測其他卡號。
- 不得在回覆、截圖檔名或報告中輸出登入密碼、HashKey、HashIV、JWT secret 或完整卡號。
- 不得刪除、重設或直接讀寫 SQLite、訂單、付款紀錄及商品資料。
- 不得呼叫任何錄影工具；錄影由使用者在外部自行處理。
- 若本次啟動測試伺服器，完成或中止後只停止本次啟動的程序。

## 執行前確認

讀取根目錄 `.env.example`，取得 `BASE_URL`、`ADMIN_EMAIL`、`ADMIN_PASSWORD` 並確認 `ECPAY_ENV=staging`。登入資料只用於表單，不得回顯。

付款固定使用：

- 國內 VISA 測試卡：`4311-9522-2222-2222`
- 有效期限：任一尚未到期的月份與年份
- 安全碼：`222`
- 3D 驗證碼：`1234`

必要欄位缺少或仍是不可用占位值時停止，僅列出缺少的欄位名稱。

Playwright MCP 必須以 `--isolated` 啟動。若本對話沒有載入隔離的 Playwright MCP，停止並說明設定問題；不得用其他瀏覽器工具替代。

## 高效操作原則

- 每次進入新頁面、送出表單後或彈窗出現時取得一次最新 `browser_snapshot`；同一穩定頁面不必在每個欄位前重複 snapshot。
- 本站登入、收件資訊等一般表單優先用一次 `browser_fill_form` 批次填寫。綠界信用卡表單是例外，必須依下一節逐欄輸入，不得使用批次填寫。
- 登入成功後再加入商品，避免訪客購物車不會合併造成重複操作。
- 依最新 snapshot 的角色、可見名稱與元素參照操作，不用固定座標。
- 只用可見畫面與本站正常回應判斷結果；URL 變化本身不算成功。
- 付款送出後先檢查是否出現「您確定使用信用卡，支付此筆訂單金額」確認彈窗；確認金額後點擊「確定」，不要誤判為表單未送出而重填資料。
- 任一步驟失敗時保存當下證據並停止可能產生額外訂單或重複付款的操作。

## 綠界信用卡欄位輸入

綠界付款頁會依賴逐字鍵盤事件更新欄位狀態。卡號即使透過 `fill` 顯示在畫面上，送出時仍可能被判定為空白，因此遵守以下規則：

- 卡號四段、有效月份、有效年份與安全碼不得使用 `browser_fill_form`，也不得使用會直接設定整欄值的 `browser_type` 預設模式。
- 第一次輸入就使用 `browser_type` 並設定 `slowly: true`，從空白欄位逐字輸入；卡號四段依畫面順序各輸入一次，等待自動換欄，未自動換欄才按 `Tab`。
- 不得先批次填入卡片資料，再逐欄補打或重填。持卡人姓名、手機、Email、帳單地址等非卡片欄位可批次填寫。
- 輸入完成後，用 `browser_find` 搜尋可見的必填或卡號錯誤訊息；避免為了檢查欄位而輸出含完整卡號的 snapshot。確認沒有錯誤再點擊「立即付款」。
- 若送出前明確顯示某個卡片欄位錯誤，只清空該欄位後以 `slowly: true` 重新輸入一次，不重填其他欄位。若已出現付款金額確認彈窗、進入 3D 驗證或送出付款，禁止再修改或重送卡片資料。

## 最短成功流程

1. 若網站尚未啟動，依專案既有方式啟動測試伺服器並記錄所啟動的程序。
2. 關閉 Playwright MCP 的舊頁面，以隔離工作階段開啟 `BASE_URL`，確認為花漾生活首頁。
3. 先登入測試帳號。
4. 回到商品頁，選擇一項有庫存商品加入購物車。
5. 開啟購物車；若帳號原本已有商品，透過畫面移除多餘項目，只保留一項且數量為 1。
6. 前往結帳，一次填入：
   - 收件人姓名：`E2E 測試收件人`
   - Email：`e2e.payment@example.com`
   - 地址：`台北市測試路 1 號`
7. 建立訂單，記錄畫面顯示的訂單編號與金額，確認只有一筆新訂單。
8. 點擊「前往綠界付款」，確認網址為 staging 網域。
9. 選擇信用卡，依「綠界信用卡欄位輸入」規則逐字輸入四段測試卡號、未來到期日及安全碼；再填入頁面要求的非個資測試持卡人資料。卡片欄位不得批次 `fill`。
10. 點擊「立即付款」。若出現 staging 提示，關閉提示後再次送出；出現付款金額確認彈窗時，核對金額並點擊「確定」。
11. 在 3D 驗證頁取得 OTP 欄位，輸入 `1234` 並送出。
12. 綠界顯示付款成功後點擊「返回商店」。
13. 本站若仍顯示待確認且提供「更新付款狀態」，最多透過該按鈕查詢 3 次，總等待不超過 60 秒。
14. 只有本站同時顯示以下內容才算通過：
    - 「付款完成」
    - 原訂單編號
    - 付款方式「綠界 ECPay」
    - 付款金額與建立訂單時相同
    - 配送狀態「準備中」

## 證據與收尾

- 成功時只需保存本站「付款完成」完整頁面截圖至 `docs/e2e/`，使用時間戳命名且不得覆寫既有檔案。
- 失敗或中止時改為保存當下可見錯誤頁面，不需額外補拍前置步驟。
- 關閉隔離瀏覽器。
- 若本次啟動伺服器，停止該程序並確認服務不再監聽；不得停止原本已在執行的服務。
- 不建立錄影檔，也不等待或檢查使用者的外部錄影。
